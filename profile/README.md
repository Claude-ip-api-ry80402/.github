<p>长期挂机最难受的不是一次掉线，而是掉线之后不知道从哪查：是本地网络断了、出口断了、会话被踢了，还是账号本身进入了验证状态。四种情况的处置动作完全不同，方向错了只会越修越乱。这篇按故障树的思路把根节点拆成三层，每层给出定位动作和处置边界，配合 API 批量开通，可以把排查时间从半天压到十几分钟。</p>
<h2>一、根节点：先确认断在哪一层</h2>
<p>根节点只有一个症状：任务中断、会话不可用。往下分三支：网络层、会话层、账号层。判断顺序是从下往上，先排除最底层的网络，再看上层。</p>
<h3>三层的区分标志</h3>
<p>网络层断：所有请求超时，换一个出口立即恢复。会话层断：请求能发出去，但返回未登录或被要求重新进入。账号层断：能登录，但要求验证或功能受限。三种表现差异明显，看一眼返回码就能分清。</p>
<h3>为什么必须按顺序查</h3>
<p>账号层的验证请求，在网络不稳时也会频繁出现。如果一上来就当成账号问题去换环境，可能把本来正常的登录态推翻。先排除网络，再动会话，最后才碰账号，这个顺序能保住大部分可恢复的状态。</p>
<h2>二、分支一：网络层</h2>
<p>网络层的排查最快，也最容易误判，因为本地通不代表出口通。</p>
<h3>本地通、出口不通</h3>
<p>先 <code>ping</code> 一个公共地址确认本地出口正常，再用出口的测试端点测一次。本地通而出口不通，问题在代理链路或上游维护。处置是切同城备用线，别在原地反复重连，重连风暴会让上游把你这条线临时限速。</p>
<h3>出口通、请求被拒</h3>
<p>出口能连通但目标返回拒绝，多半是出口地址在目标侧被限制。这时候的动作是核对这条线近期的使用记录：是否有高并发、是否有大流量下载。有的话换线并降速，没有的话联系供应商核查该段地址的状态。</p>
<h3>延迟突然翻倍</h3>
<p>先看是不是自己这边的并发上去了。同一出口十个号同时跑长任务，延迟翻倍属正常；并发没变而延迟翻倍，多半是上游链路拥塞，换时段复测，连续两个时段都不恢复就换线。</p>

<h2>三、分支二：会话层</h2>
<p>会话层的问题表现是「能发请求但不像原来那个我」，处置重点是保住环境，不要重装。</p>
<h3>被踢下线但没有验证</h3>
<p>多数是同一账号在别处登录，或者出口地址发生了变化。先查出口地址是否与档案一致，不一致说明线路被调度过，需要切回原线并重登；一致则查是否有其他设备在用同一账号。</p>
<h3>登录态丢失但环境没变</h3>
<p>检查浏览器配置是否被改动过，尤其是 UA、时区、语言三项。模板升级、插件自动更新都可能改动这些参数。恢复方法是从备份还原配置再登录，不要直接新建环境，新建等于从零开始养。</p>
<h3>API 调用频繁超时</h3>
<p>先看是不是单号请求过密。给每个号设独立限速，比如每分钟不超过十次请求，超时率通常立刻下降。限速比换线更有效，因为超时的根因往往是自己的调用方式。</p>
<h2>四、分支三：账号层</h2>
<p>到了账号层，说明网络与会话都已经排除，处置要谨慎，动作幅度越小越好。</p>
<h3>要求二次验证</h3>
<p>先确认出口归属地与账号注册地是否一致，这一步能解释相当一部分验证。归属地对得上仍然被要求验证的，按平台提供的正常流程完成验证，不要尝试绕过，也不要频繁重试，重试过多会让状态更差。</p>
<h3>功能受限</h3>
<p>暂停该号的自动化任务，改为人工低频使用几天，观察是否恢复。同时把这个号从批量任务里摘出来，避免影响同批其他号。恢复后先做低强度任务，别一上来跑长文档。</p>

<h3>批量开通接口的价值在恢复速度</h3>
<p>手工配十条线要半天，接口开通十分钟能起一批。掉线集中爆发时，恢复速度直接决定损失大小。接入前先确认接口能返回通道状态与环境参数，只有开通没有状态查询的接口价值有限。</p>
<h3>恢复后必须做的一件事</h3>
<p>把故障现象、定位层级、处置动作、恢复时间写进台账。同一个号一个月内出现两次同类故障，就该换线而不是继续修，这是判断线路寿命的依据。</p>
<h2>常见问答</h2>
<h3>掉线后一直重连可以吗？</h3>
<p>答：不建议。高频重连会让上游把这条线当异常流量，反而延长恢复时间。设个退避节奏，三十秒、两分钟、五分钟各试一次，三次不通就走换线流程。</p>
<h3>怎么快速判断是线路问题还是账号问题？</h3>
<p>答：拿同一条出口上的另一个号试一下。另一个号正常，问题在这个号；另一个号也异常，问题在线路。这个动作一分钟内能完成，比翻日志快。</p>
<h3>备用线一定要同城吗？</h3>
<p>答：建议同城。跨城市切换等于换了登录地区，触发的验证可能比掉线本身更麻烦。同城不同运营商也可以，归属地一致就行。</p>
<h3>接口批量开通会不会很容易配错？</h3>
<p>答：会，所以要做两件事：开通前用模板固定参数，开通后自动核对归属地与城市。核对不通过的通道不进生产池，这条规则能挡掉大部分配错。</p>
